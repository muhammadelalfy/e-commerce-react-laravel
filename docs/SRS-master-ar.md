## 1. المقدّمة

### 1.1 الغرض
تحدّد هذه الوثيقة **كل** متطلبات ومنطق أعمال منصّة «أوفرز» — الوظيفية وغير الوظيفية وقواعد العمل التفصيلية لكل وحدة — بحيث تكون مرجعاً كاملاً لفريق التطوير ولبناء خادم خلفي (Backend) مطابق تماماً لما هو منفَّذ حالياً في الواجهة الأمامية.

### 1.2 النطاق
أوفرز سوق إلكتروني متعدد المتاجر يجمع متاجر ومراكز تقدّم **خصومات فعّالة**، ويعرضها حسب الموقع الجغرافي والقسم. يقوم على أربعة أعمدة رئيسية:
1. **خصومات أوفرز** — منتجات وعروض بخصم فعّال ومحدّد بوقت.
2. **مزادات أوفرز** — مزايدة مباشرة على قطع مختارة.
3. **تسوّق مع أوفرز** — تصفّح وشراء من المتاجر.
4. **خدمات أخرى** — ريلز، فعاليات، خريطة متاجر، كوبونات، وأدوات بائعين متكاملة.

### 1.3 أدوار المستخدمين
| الدور | الوصف |
|---|---|
| **العميل (USER)** | يتصفّح الخصومات/الأقسام/المتاجر، يزايد في المزادات، يحفظ المفضّلة، يستخدم كوبونات الخصم، يشاهد الريلز/الفعاليات/الخريطة، يُتمّ الطلب. |
| **البائع (VENDOR)** | يملك لوحة تحكم كاملة لمتجره: المنتجات، العروض المموّلة، الكوبونات (CRUD كامل)، الطلبات، الاشتراك في باقة إعلانات، مواقع الفروع، بروشور المتجر، الإعدادات. |
| **المدير (ADMIN)** | يشرف على المستخدمين والمتاجر، يوافق على المنتجات وطلبات الانضمام، يدير الدول/المدن/المندوبين/باقات الإعلانات/الاشتراكات/الريلز/محتوى التطبيق. |
| **ريلز فقط (REELS_ONLY)** | دور مخصّص لمستخدم يُنشئ محتوى ريلز فقط دون صلاحيات بائع كاملة. |

### 1.4 بيئة التشغيل
- أي متصفّح حديث؛ تصميم متجاوب بالكامل (جوال/لوحي/سطح مكتب).
- الإصدار الحالي بلا خادم خلفي — البيانات في وحدات مكتوبة النوع (TypeScript) + `localStorage` للحالة المشتركة، والبنية **جاهزة للربط بـ API** دون تغيير واجهة الاستهلاك.

## 2. المبادئ العامة للنظام
- كل كيان يحمل **`id`** فريداً، وحقول ثنائية اللغة تُخزَّن كحقلين منفصلين (`ar` / `en`).
- المصادقة عبر JWT مقترحة؛ الأدوار: `USER` · `VENDOR` · `ADMIN` · `REELS_ONLY`. المسار الأساسي المقترح للـ API: `/api/v1`.
- **نمط «المخزن المشترك» (Store):** كل وحدة بيانات في الواجهة (couponStore، offerStore، catStore، geoStore، adPackageStore، repStore، storeStore، vendorProfileStore) مبنية على **مصنع مخزن عام واحد (`createStore`)** يوفّر: قراءة/كتابة الحالة، الاشتراك التفاعلي (Observer)، والحفظ التلقائي في `localStorage`. هذا يعني أن كل وحدة في الخلفية = جدول/خدمة واحدة بنفس عمليات (add/update/remove/toggle/list)، ومصدر بيانات واحد تتشارك فيه كل الواجهات (مثال: كوبون يُنشئه التاجر يظهر فوراً في الموقع).
- الحقول المحسوبة (الخصم %، تاريخ الانتهاء، السعر لكل مدة، الوقت المتبقّي، «لديه عروض») تُحسب في الخادم وتُرسل جاهزة للعرض.
- التصفية حسب المدينة تعتمد على `userCity` المرسل مع الطلب أو من ملف المستخدم.
- الحذف يُفضَّل أن يكون منطقياً (soft-delete) للكيانات المهمّة (المنتجات، المتاجر).

## 3. المصادقة والمستخدمون (Auth & Users)

### الكيان: User
| الحقل | النوع | الوصف |
|---|---|---|
| id | uuid | المعرّف |
| name | string | الاسم |
| email | string (unique) | البريد |
| phone | string | الجوال |
| role | enum | `USER` · `VENDOR` · `ADMIN` · `REELS_ONLY` |

**قواعد العمل:**

- **التسجيل كتاجر** يفتح تدفّق **«طلب متجر» (StoreApplication)** بحالة `PENDING` بانتظار موافقة الإدارة — لا يُنشأ متجر فعليّ إلا بعد الموافقة (انظر §6).

**Endpoints:** `POST /auth/register` · `POST /auth/login` · `GET /auth/me` · `PATCH /users/{id}`

## 4. الدول والمدن (Geo)

### الكيانات: Country, City
| الحقل | النوع | الوصف |
|---|---|---|
| Country.id | string | معرّف الدولة (مثل `sa`) |
| Country.ar/en | string | الاسم بالعربية/الإنجليزية |
| Country.flag | صورة SVG | علم حقيقي (وليس إيموجي) |
| Country.dial | string | مفتاح الاتصال الدولي |
| City.id | string | معرّف المدينة |
| City.ar/en | string | اسم المدينة |
| City.country | fk → Country | الدولة التابعة |
| City.stores | int | عدد المتاجر في المدينة |

**قواعد العمل:**
- اختيار الدولة إجباري قبل اختيار المدينة؛ المدن تُفلتَر حسب `city.country`.
- المدن تُجلب من مصدر خارجي (CountriesNow API) عند إضافة دولة جديدة عبر الإدارة.
- **أسماء المدن بالعربية:** المدن القادمة من المصدر الخارجي (إنجليزية) تُترجَم للعربية عبر خريطة مُعدّة مسبقاً للمدن الكبرى (الرياض، جدة، دبي، الدوحة، المنامة، مسقط…)، ثم **ترجمة صوتية آلية (transliteration)** احتياطية لأي مدينة غير موجودة في الخريطة، بحيث **لا يظهر أي اسم إنجليزي** في الواجهة العربية مهما كان مصدر البيانات.
- **الأعلام** تُعرَض كصور SVG حقيقية (وليس رموز إيموجي) لضمان ظهورها على كل الأنظمة — نظام ويندوز تحديداً لا يعرض إيموجي الأعلام (يظهر الحرفان فقط، مثل «SA»).
- يُطلب إذن الموقع الجغرافي من المتصفّح **مرة واحدة عند دخول الموقع**؛ تُستخدم الإحداثيات لعرض «أقرب متجر لديه عروض» (انظر §12).

**Endpoints:** `GET /countries` · `GET /countries/{id}/cities` · `POST /admin/countries` · `POST /admin/cities` · `DELETE /admin/cities/{id}`

## 5. الأقسام والأقسام الفرعية (Categories)

### الكيانات: Category, SubCategory
| الحقل | النوع | الوصف |
|---|---|---|
| Category.id, ar, en, icon | string | القسم واسمه وأيقونته |
| SubCategory.id, ar, en | string | القسم الفرعي |

**قواعد العمل:**

**Endpoints:** `GET /categories` · `GET /categories/{id}/subcategories` · `GET /categories/{catId}/subcategories/{subId}/stores` · إدارة: `POST`/`DELETE /admin/(sub)categories`

## 8. تجربة الاكتشاف في الصفحة الرئيسية (Home Discovery Tabs)

شريط تبويبات أفقي فوق السلايدر الرئيسي يعمل **كمعالج (wizard)**: يظهر محتوى التبويب المختار **فقط** — وليس تمرير داخل نفس الصفحة. عند اختيار أي تبويب غير «الأقسام» يُخفى السلايدر وشريط «عروض ساخنة».

| التبويب | المحتوى / المنطق |
|---|---|
| **الأقسام** | الافتراضي — السلايدر (حلقة لا نهائية بعرض شرائح جانبية جزئية) + شريط عروض ساخنة (نص متحرّك) + «تسوّق حسب القسم». |
| **المنتجات** | مجموعة منتجات في الصفحة؛ «عرض الكل» يفتح صفحة المتجر الكاملة. |
| **العروض** | كل العروض النشطة (`active && discount > 0`)، مع فلاتر داخلية: شرائح الأقسام + ترتيب (مختار لك / **الأحدث** / الأقل سعراً / الأعلى سعراً / الأعلى تقييماً / أكبر خصم). «الأحدث» = ترتيب تنازلي حسب `days`. |
| **٥٠٪ وأكثر** | العروض ذات `discount ≥ 50` فقط — تبويب مستقل عن «العروض» لإبراز أكبر الخصومات. |
| **أكواد الخصم** | لوحة كوبونات مخصّصة (وليست منتجات) — انظر §9. |
| **متاجر مميزة** | بطاقات المتاجر. |
| **ريلز** | يوجّه لصفحة الريلز. |

**قواعد إضافية:**
- كل تبويب «عروض» له فلتر منتجات خاص فيُظهر محتوىً مختلفاً فعلياً (وليس نفس القائمة بعناوين مختلفة).
- شريط التبويبات صفّ أفقي واحد بلا التفاف؛ يتمرّر أفقياً على الجوال دون شريط تمرير مرئي.
- بحث الصفحة الرئيسية بمقدّمة ثابتة «ابحث عن» وكلمة متغيّرة تُكتب وتُمحى تلقائياً (منتج · كاش باك · كوبون خصم · متجر).

**Endpoints:** `GET /products?active=true&discount_gt=0&sort=latest|discount|price|rating` · `GET /products?discount_gte=50`

## 9. الكوبونات وأكواد الخصم (Coupons)

| الحقل | النوع | الوصف |
|---|---|---|
| id, code, vendor | mixed | الرمز والمتجر |
| type | enum | `percent` (نسبة٪) · `fixed` (مبلغ ثابت ﷼) · `item` (بالصنف) |
| pct | number | النسبة أو المبلغ (٠ لنوع `item`) |
| buyQty, giftQty | number? | لنوع «بالصنف»: اشترِ X واحصل على Y مجاناً |
| used, limit, active, until | mixed | الاستخدام، الحدّ، الحالة، تاريخ الانتهاء |

**قواعد العمل:**
- إدارة الكوبونات **للتاجر فقط** عبر لوحة المتجر (أُزيلت بالكامل من لوحة الإدارة). لكل كوبون **CRUD كامل**:
  - **إنشاء** — نموذج يختار النوع (نسبة/مبلغ ثابت/بالصنف) ويولّد كوداً تلقائياً إن لم يُدخله التاجر.
  - **تعديل** — يفتح النموذج **معبّأً بالقيم الحالية** للكوبون المختار.
  - **حذف** — بتأكيد من التاجر قبل الحذف الفعلي.
  - **تفعيل/إيقاف** — مفتاح تبديل سريع دون فتح نموذج.
- التاجر يملك كوبوناته فقط (لا يرى كوبونات تاجر آخر).
- **مصدر واحد مشترك**: أي عملية من لوحة التاجر (إضافة/تعديل/حذف/تفعيل) تنعكس **فوراً** على الموقع دون إعادة تحميل الصفحة.
- تبويب **«أكواد الخصم»** في الصفحة الرئيسية يعرض **الكوبونات النشطة فقط** (`active = true`) كبطاقات — وليس منتجات. الكوبون المُوقَف أو المحذوف يختفي من الموقع مباشرة.
- **بطاقة الكوبون** تعرض: اسم المتجر (رابط لصفحته) · القيمة (٪ / ﷼ / X+Y هدية) · تاريخ الانتهاء · الوصف · شريط الكود.
- **النسخ بالضغط:** الضغط على شريط الكود **ينسخه تلقائياً إلى الحافظة** (Clipboard API مع احتياطي `execCommand` لضمان العمل حتى في بيئات مقيّدة)، ويُظهر تأكيداً بصرياً «تم النسخ» لمدة قصيرة ثم يعود لحالته.
- عند إضافة كوبون جديد من التاجر، يُرسَل **إشعار للإدارة** (`AdminNotice`) يحمل المتجر والكود والنسبة ووقت الإضافة، ويظهر في شارة إشعارات الإدارة.
- حساب قيمة الخصم الفعلي: `percent` → `price × (1 - pct/100)` · `fixed` → `price - pct` · `item` → أرخص Y صنف من بين المشتريات مجاناً عند شراء X.
- شارة كوبون تظهر على بطاقة أي منتج تابع لمتجر له كوبون `active`.

**Endpoints:** `GET /coupons?active=true` (لتبويب الموقع) · `GET /vendors/{id}/coupons` · `POST`/`PUT`/`DELETE /vendors/{id}/coupons` · `PATCH /vendors/{id}/coupons/{cid}/toggle` · `POST /coupons/validate` (code + cart)

## 10. باقات الإعلانات والاشتراكات (Ad Packages)

### الكيان: AdPackage
| الحقل | النوع | الوصف |
|---|---|---|
| id, ar, en, ads, price | mixed | الاسم، عدد الإعلانات المسموح، السعر |
| period | enum | `week(7)` · `month(30)` · `6months(180)` · `year(365)` (بالأيام) |
| start, autoRenew, renewPrice, active | mixed | البداية، التجديد التلقائي وسعره، الحالة |

### الكيان: AdSub (اشتراك متجر في باقة)
**قواعد العمل:**
- تاريخ الانتهاء يُحسب: `end = start + PERIOD_DAYS[period]`. الاشتراك «منتهٍ» إذا `end < today`.
- سعر أي مدة يُشتقّ من سعر أساسي واحد: `priceForPeriod = round((price / PERIOD_DAYS[base]) × PERIOD_DAYS[target])` — تُعرض **كل المدد** على بطاقة الباقة (أسبوعي/شهري/٦ أشهر/سنوي) دون الحاجة لسعر منفصل لكل مدة.
- التمديد (Extend): يُعاد ضبط `start = today` و`end = today + period` (تجديد يدوي من اليوم).
- التجديد التلقائي قابل للتبديل لكل اشتراك على حدة.
- عدد الإعلانات النشطة للتاجر مرتبط مباشرة بحدّ `ads` في باقته (انظر §11).

**Endpoints:** `GET /ad-packages` · `POST /vendors/{id}/subscribe` (packageId, start) · `POST /vendors/{id}/subscription/extend` · `DELETE /vendors/{id}/subscription` · `PATCH /vendors/{id}/subscription/auto-renew` · إدارة: `GET /admin/subscriptions`

## 11. العروض المموّلة (Sponsored Offers / Ads)

| الحقل | النوع | الوصف |
|---|---|---|
| id, vendor, cat, subcat, img | mixed | الروابط وصورة العرض |
| ar, en, discount | mixed | العنوان ونسبة الخصم |
| start, end, active | mixed | الفترة والحالة |

**قواعد العمل:**
- عدد العروض النشطة للتاجر **≤ `ads`** في باقته المشترك بها (يُسمّى `atLimit`). لا يمكن إضافة عرض جديد إن اكتمل العدد أو انتهى الاشتراك.
- **الوقت المتبقّي** (حتى نهاية يوم `end`) يُعرض بوحدة ذكية: أقل من ساعة → **دقائق** · أقل من يوم → **ساعات** · أقل من ٣ أيام → **أيام** · غير ذلك → **التاريخ الكامل** — ويتحوّل الشريط للون العاجل قرب الانتهاء.
- صورة العرض تُستخدم كخلفية بطاقة المتجر في «تسوّق حسب القسم».

**Endpoints:** `GET /offers?vendor=&active=` · `POST`/`PUT`/`DELETE /vendors/{id}/offers`

## 12. مواقع فروع المتجر (Store Branches) والموقع الجغرافي

### الكيان: StoreBranch
| الحقل | النوع | الوصف |
|---|---|---|
| id, vendor | fk | المتجر |
| ar, en | string | اسم الفرع |
| cityAr, cityEn | string | مدينة الفرع (تطابق أسماء المدن) |
| addressAr, addressEn, phone | string | العنوان والهاتف |
| lat, lng (أو x,y) | number | الإحداثيات على الخريطة |

**قواعد العمل:**
- **صفحة المتجر** تعرض فروع المتجر **في مدينة الزائر فقط**: `branches.filter(b => b.city == userCity)`. إن لم توجد فروع في مدينته تُعرض قائمة المدن المتاحة كبديل.
- **الموقع الجغرافي وأقرب متجر:** يُطلب إذن الموقع من المتصفّح مرة واحدة عند الدخول؛ تُخزَّن الإحداثيات؛ خريطة المتاجر تُبرز **أقرب متجر لديه عروض** مرتّبة تصاعدياً حسب المسافة (حساب المسافة المقترح على الخادم = صيغة Haversine)، مع أولوية للمتاجر «التي لديها عروض» (انظر §7).
- أيقونة الوصول لأقرب متجر في شريط التنقّل هي **علامة خرائط Google الرسمية** (أصل صورة حقيقي وليس رسماً مركّباً)، لضمان تعرّف فوري من المستخدم.

**Endpoints:** `GET /vendors/{id}/branches?city={userCity}` · `POST`/`DELETE /vendors/{id}/branches` · `GET /stores/nearest?lat=&lng=&hasOffers=true`

## 13. المزادات (Auctions)

| الحقل | النوع | الوصف |
|---|---|---|
| id, vendor, cat | fk | الروابط |
| ar, en | string | اسم القطعة |
| current, start | number | المزايدة الحالية والابتدائية |
| bids | number | عدد المزايدات |
| endH | number | ساعات حتى الانتهاء (من لحظة تحميل الصفحة) |

**قواعد العمل:**
- مزاد مباشر مميّز في أعلى الصفحة مع عدّاد تنازلي حيّ (ساعات:دقائق:ثوانٍ يُحدَّث كل ثانية) وزر «زايد الآن».
- **قاعدة المزايدة:** كل ضغطة «زايد الآن» ترفع المزايدة الحالية بمقدار ثابت (**+50** في النسخة الحالية، ويُقترح جعله `minIncrement` قابلاً للتهيئة لكل قطعة في الخادم)، وتزيد عدّاد المزايدات بواحد، وتُعلّم المستخدم كـ«صاحب أعلى مزايدة حالياً» (`mine`).
- المزاد **ينتهي** تلقائياً عند وصول العدّاد التنازلي للصفر (`endsAt`)؛ زر المزايدة يتعطّل ويظهر «انتهى».
- إن كان المستخدم صاحب أعلى مزايدة، يظهر الزر بحالة «فزت» بدل زر المزايدة العادي.
- شبكة مزادات موازية تعرض كل قطعة ببطاقة مستقلة: صورة، شارة عدد المزايدات، اسم البائع، المزايدة الحالية، وعدّاد خاص بها.

**Endpoints:** `GET /auctions` · `POST /auctions/{id}/bid` · `GET /auctions/{id}` (تفاصيل + المزايدات)

## 21. الصفحات التعريفية والقانونية
من نحن، الأسعار، الأسئلة الشائعة، تواصل معنا، الوظائف، المدونة، والقانونية (الشروط والأحكام، سياسة الخصوصية، الشحن والتوصيل، الإرجاع والاستبدال).

**تذييل الصفحة (Footer):** روابط مجمّعة في أربع مجموعات (أوفرز، للبائعين، المساعدة، الشركة) + شارات وسائل الدفع. على الجوال، كل مجموعة روابط **تنطوي كقائمة قابلة للطيّ (accordion)** لتقصير التذييل، وتبقى مفتوحة بالكامل على الشاشات الكبيرة.

## 22. متطلبات الواجهة والتصميم

- **نظام تصميم** بمتغيّرات CSS محدّدة: علامة مرجانية/وردية (`--brand`)، إبرازات ذهبية (`--gold`)، حبر كحلي للنص (`--text`)، أسطح متغيّرة حسب الوضع الفاتح/الداكن.
- **الخطوط:** Cairo / Tajawal / Noto Sans Arabic (عربي)، Inter (لاتيني).
- **الأرقام:** معزولة بصنف (`.num`) لتظهر من اليسار لليمين داخل السياق العربي.
- **الحركة:** GSAP لكل التأثيرات (ظهور تدريجي، نص متحرّك، شريط لا نهائي، سلايدر بحلقة لا نهائية بشرائح جانبية جزئية الظهور).
- **القائمة المصغّرة على الجوال:** نافذة صغيرة متحرّكة (تكبير + تلاشٍ) تنسدل **مباشرة أسفل زرّ القائمة** دون فراغ ودون تغطية الترويسة، مع ظهور تباعي لعناصرها.
- **الأيقونات بلا صناديق:** عناصر مثل شارة الدولة وأيقونة الخريطة تُعرض كأيقونات نظيفة دون إطار أو خلفية.
- التخطيطات متجاوبة بالكامل مع انعكاس صحيح للاتجاهين عبر خصائص CSS المنطقية (`inset-inline`، إلخ) وليس تصاميم يدوية منفصلة لكل اتجاه.

## 24. ملاحظات تنفيذية لبناء الـ Backend

- كل «مخزن» (store) في الواجهة (couponStore · offerStore · catStore · geoStore · adPackageStore · repStore · storeStore · vendorProfileStore) يقابله **جدول أو خدمة واحدة في الخلفية** بنفس العمليات (add/update/remove/toggle/list)، وجميعها اليوم مبنية على نمط نشر/اشتراك (Observer) موحّد في الواجهة — أي تغيير في مصدر واحد ينعكس فوراً على كل المستهلكين (مثال حيّ: كوبون التاجر ↔ تبويب الموقع).
- الحقول المحسوبة (الخصم %، تاريخ الانتهاء، السعر لكل مدة، الوقت المتبقّي، «لديه عروض») تُحسب على الخادم وتُرسل جاهزة، وتُعاد صياغتها للعرض فقط في الواجهة.
- رفع الملفات (شعار/غلاف/بروشور/صور/فيديو ريلز) عبر تخزين كائنات متوافق مع S3، مع إرجاع URL والتحقّق من النوع والحجم.
- التصفية حسب المدينة (العروض/الفروع/الفعاليات/المدن) تعتمد على `userCity` المُرسل مع الطلب أو من ملف المستخدم، مع دعم **ترجمة/تحويل صوتي تلقائي** لأسماء المدن غير العربية المصدر.
- الصلاحيات: كل endpoint إداري يتطلّب دور `ADMIN`؛ endpoints المتجر تتطلّب ملكية المورد (`vendor owns resource`)؛ عمليات الكوبونات تتطلّب أن يكون التاجر مالك الكوبون تحديداً.
- الأعلام والأيقونات الرسمية (خرائط Google، أعلام الدول) تُخزَّن كأصول ثابتة حقيقية (SVG) بدل الاعتماد على خطوط/إيموجي النظام، لضمان اتساق العرض عبر كل الأنظمة والمتصفّحات.
